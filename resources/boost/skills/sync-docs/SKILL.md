# Sync docs: find and fix drift

A sweep so a fresh session, an agent and a visitor read only what is true today. The enemy is drift: a claim that stopped matching the code, and residue that narrates how something changed instead of what it is. Every claim resolves to a file, a migration, a route, a config key, a test or a dated measurement.

## The imprint's half

This method is the foundry's and the same in every imprint. What differs lives in the imprint, in `.ai/sync-docs.md`. Read it first, whole. Its sections:

- **Solo**: the project the scratchpad goes in, and where work that needs building goes.
- **Surfaces**: what counts as a doc here, where it lives, and what is not a doc.
- **Areas**: one row per area, the docs it owns and the truth it is checked against.
- **Ground truth**: what to read before fanning out.
- **Rounds**: what a round ends with beyond this method, and the test command.
- **Checks**: the imprint's own checks, on top of the residue checklist.

No `.ai/sync-docs.md`? Stop and say so. Offer a draft of one from the imprint's layout, and write it only on Mischa's word.

## Where the work lives

Findings and the fix plan live in a Solo scratchpad in the imprint's project: `mcp__solo__scratchpad_write` for a new pass, `scratchpad_append_section` to add a round, `scratchpad_read` to resume one. Fix rounds are sections of that same scratchpad.

## What every imprint holds the same

- `CLAUDE.md`, `AGENTS.md` and the skills directories Boost writes (`.claude/skills/`, `.agents/skills/` and the like) are generated by `php artisan boost:install` and never edited by hand. A finding in one is filed against its source: a guideline in `.ai/guidelines/`, a skill in `.ai/skills/`, or the foundry.
- The foundry is read under `vendor/steddle/foundry` and never edited there. A finding in the foundry, this skill included, is filed against `~/Github/steddle/foundry`.
- `.ai/sync-docs.md` is a doc like any other, audited by the area that owns the setup files.

## Method: audit, then act

An audit and a fix in the same pass hides its own blast radius. Read-only first, synthesize, get Mischa's go-ahead, then edit in scoped rounds.

1. **Ground truth first.** Read what `.ai/sync-docs.md` lists under Ground truth, and `git log --oneline -30`: recent commits are where drift concentrates.
2. **Fan out one read-only agent per area**, or only the area Mischa named. Give each its row from Areas, the Surfaces table, this file, the residue checklist and the imprint's Checks. Judgement is the job, so run them on the session's own model, not the subagent default. Each returns `file:line | category | evidence | proposed action`, ranked.
3. **Verify the fan-out stayed read-only.** `git status --short` before and after must match.
4. **Synthesize into the scratchpad**: one 'Findings' section per area; one flat 'Decisions for Mischa' list for anything that is not a mechanical fix (operative text, a claim that might be a product decision, a feature a doc promises and the code lacks); one 'Bugs and dead code' list for what the sweep tripped over.
5. **Report and stop.** Show Mischa the scratchpad. Edit nothing yet.
6. **On 'go', fix in edit-scoped rounds**, one round per concern (one guideline or rule file, docblocks in one directory, MCP prose, mail copy, site copy, one docs topic), never a round that touches both a guideline and code comments. A round ends with the checklist re-run against the files it touched, and:
   - after a guideline or a skill under `.ai/`: `php artisan boost:install --guidelines --skills --no-interaction`, both flags, since `--guidelines` alone renders `CLAUDE.md` and `AGENTS.md` without their skills section. `git status` then shows those two files and nothing else, or the run pulled in a vendor skill update that belongs in its own commit.
   - after a view: `npm run build` and the tests that assert its strings.
   - whatever the imprint's Rounds section adds.
7. **Verify before reporting done.** Re-grep the changed files for residue. Confirm every count against the source (`grep -c`, `php artisan route:list`, a migration, a query). If PHP changed, `vendor/bin/pint` on the changed files, never `--dirty`, since other sessions share the tree, then the imprint's test command.

## Write the end state

Every rewrite reads as if the current state was always true. Never narrate the change.

- Banned in prose: `now`, `no longer`, `previously`, `used to`, `instead of`, `the old`, `before` where it means an earlier build. A line that teaches the reader something used to exist gets rewritten to describe only what exists.
- A reason survives the rewrite; the story of how it was learned does not. Keep a measurement as a dated fact about the data, and drop the narration of the build that produced it.
- A dated measurement is not drift. 'Measured on 2026-08-20: 24.079 rows' stays true. It is a finding only when undated, when what it measured is gone, or when the code contradicts the conclusion drawn from it.
- A migration's docblock may describe its conversion: what the table held, what it holds after, and why. Only a false sentence in one is a finding.
- History lives in git, Solo and the imprint's journal where it keeps one, never in a guideline, a docblock, a tool description or site copy.

## Residue checklist

- Transition language, see above.
- Stale counts. Every undated number stated as current ('four tools', 'nine tables', '16 articles') is re-derived from source, not trusted.
- Dead pointers. Every path, class, method, command, route, config key, env var, tool, prompt, resource URI or `{@see}` a doc cites still exists under that name, and every link in site copy, docs and mails resolves.
- Comments detached from their code: a docblock above the wrong member, two stacked docblocks, a sentence split from its antecedent by a later insertion.
- Scratchpad, brief or session references left in prose after a rewrite.
- A comment that restates the code, narrates or decorates. A comment carries what the code cannot: a reason, a trap, a constraint, a dated measurement.
- Mischa's style: no em or en dashes, no middle dot as a separator (` | ` between metadata, a comma inside a phrase), none of the banned words in his writing rules.

## Checks in every imprint

- **The same fact typed more than once.** A status list, a tool list, a limit or a lifetime stated in code, copy, docs, MCP instructions and legal pages. Two statements that disagree are a finding; so is a copy that did not need to exist when a class constant, a config key or `resources/content` already holds it. The imprint's Checks name its facts.
- **Overclaims.** A sentence that promises more than the code keeps: enforceability, a review nobody did, 'nothing can be deleted', 'every call is logged'. Check each against the code. The imprint's Checks name the phrases it is prone to.
- **The code is not always the fixed side.** For each mismatch the auditor says which side should yield and why. Where the code should, it goes under bugs; where the doc should, it is a doc finding.
- **Silence is a finding.** Something that exists and no doc mentions is listed, never filled in with what a doc might say.

## Flag, don't silently fix

A drift sweep surfaces real bugs and dead code along the way. Don't fix them mid-sweep: note them in 'Bugs and dead code'. Fix only the doc mismatch itself.

## What not to do

- Edit anything before Mischa says go. The audit is read-only.
- Hand-edit a generated file, or edit what the imprint's Surfaces mark as never edited in a round.
- Run one round across both a guideline and code comments.
- Cut a fact to make a comment shorter. A reason, a constraint or a dated measurement stays; prose around it goes.
- Assert a count or a claim without re-deriving it from the source.
- Commit or push. That's Mischa's call.
